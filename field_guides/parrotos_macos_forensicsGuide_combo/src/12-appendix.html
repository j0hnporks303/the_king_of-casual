AThe full Parrot / Debian install script

Everything this manual uses, in one place. Read it before running it; it installs a lot and builds several things from source.

#!/usr/bin/env bash
# macOS/APFS forensics toolchain for Parrot OS / Debian
set -euo pipefail
TOOLS="$HOME/tools"; mkdir -p "$TOOLS"

### 1. base system -----------------------------------------------------
sudo apt update
sudo apt install -y \
  build-essential cmake git pkg-config autoconf automake libtool flex bison \
  dkms linux-headers-"$(uname -r)" \
  libfuse3-dev fuse3 libbz2-dev zlib1g-dev libssl-dev libattr1-dev \
  python3-dev python3-pip python3-venv \
  cargo rustc

### 2. imaging and evidence handling ----------------------------------
sudo apt install -y \
  ewf-tools libewf-dev afflib-tools \
  gddrescue dc3dd dcfldd guymager \
  hashdeep

### 3. classical forensics --------------------------------------------
sudo apt install -y \
  sleuthkit libtsk-dev autopsy \
  testdisk foremost scalpel bulk-extractor binwalk magicrescue \
  sqlite3 sqlitebrowser libplist-utils \
  exiftool yara radare2 clamav xxd ent jq

### 4. APFS access engines --------------------------------------------
# 4a. apfs-fuse — day-to-day mounting, snapshots, compression
git clone https://github.com/sgan81/apfs-fuse.git "$TOOLS/apfs-fuse"
cd "$TOOLS/apfs-fuse" && git submodule update --init
mkdir -p build && cd build
cmake .. -DUSE_FUSE3=ON && make -j"$(nproc)" && sudo make install && sudo ldconfig

# 4b. libyal libfsapfs — metadata depth, encryption, plaso backend
git clone https://github.com/libyal/libfsapfs.git "$TOOLS/libfsapfs"
cd "$TOOLS/libfsapfs"
./synclibs.sh && ./autogen.sh
./configure --enable-python --with-libfuse
make -j"$(nproc)" && sudo make install && sudo ldconfig

# 4c. kernel module + apfsprogs — speed and apfsck
git clone https://github.com/linux-apfs/linux-apfs-oot.git "$TOOLS/linux-apfs-oot"
cd "$TOOLS/linux-apfs-oot" && make -j"$(nproc)" && sudo make install
sudo depmod -a && sudo modprobe apfs
git clone https://github.com/linux-apfs/apfsprogs.git "$TOOLS/apfsprogs"
for p in apfsck apfs-snap apfs-label; do
  ( cd "$TOOLS/apfsprogs/$p" && make -j"$(nproc)" && sudo make install )
done

### 5. python environment ---------------------------------------------
python3 -m venv "$TOOLS/venv-dfir"
source "$TOOLS/venv-dfir/bin/activate"
pip install --upgrade pip wheel
pip install \
  plaso pytsk3 pyewf construct \
  lief flare-capa capstone \
  biplist ccl-bplist nska-deserialize ds-store \
  pandas python-dateutil xlsxwriter

### 6. macOS artifact parsers ------------------------------------------
cd "$TOOLS"
for r in ydkhatri/mac_apt \
         mandiant/macos-UnifiedLogs \
         ydkhatri/UnifiedLogReader \
         dlcowen/FSEventsParser \
         ydkhatri/spotlight_parser \
         mac4n6/APOLLO \
         n0fate/chainbreaker \
         Yara-Rules/rules ; do
  git clone --depth 1 "https://github.com/$r.git" || true
done
pip install -r "$TOOLS/mac_apt/requirements.txt"

# the Mandiant unified-log parser is Rust
( cd "$TOOLS/macos-UnifiedLogs" && cargo build --release --examples )

# Apple code-signature verification on Linux
cargo install apple-codesign

### 7. SQLite recovery --------------------------------------------------
cd "$TOOLS"
git clone https://github.com/inflex/undark.git && ( cd undark && make )
git clone https://github.com/n0fate/walitean.git || true

### 8. record what was installed ---------------------------------------
{ date -u +%FT%TZ; uname -a
  for d in "$TOOLS"/*/; do
    [ -d "$d/.git" ] && echo "$(basename "$d") $(git -C "$d" rev-parse --short HEAD)"
  done
  pip freeze; } > "$TOOLS/toolchain-manifest.txt"
echo "done — manifest at $TOOLS/toolchain-manifest.txt"

# a one-liner that handles the common cases
cat > ~/bin/ts <<'PY'
#!/usr/bin/env python3
import sys, datetime as dt
v = float(sys.argv[1]); kind = sys.argv[2] if len(sys.argv) > 2 else 'mac'
o = {'unix':0, 'mac':978307200, 'cocoa':978307200, 'hfs':-2082844800}
if kind == 'webkit': u = v/1e6 - 11644473600
elif kind == 'apfs': u = v/1e9
elif kind == 'firefox': u = v/1e6
else: u = v + o[kind]
print(dt.datetime.utcfromtimestamp(u).strftime('%Y-%m-%d %H:%M:%S UTC'))
PY
chmod +x ~/bin/ts

▸ TIP — THE SANITY CHECK

Result in 1988? You treated Mac absolute time as Unix. Result in 2058? You added the offset twice. Result in 1601 or 1904? You used the wrong epoch entirely. These three mistakes account for nearly every timestamp error in macOS forensics, and all three are obvious on sight.

DSQLite query cookbook

Quarantine — download history

SELECT datetime(LSQuarantineTimeStamp + 978307200,'unixepoch') AS ts,
       LSQuarantineAgentName   AS agent,
       LSQuarantineDataURLString   AS file_url,
       LSQuarantineOriginURLString AS referrer
FROM LSQuarantineEvent ORDER BY ts DESC;

knowledgeC — application focus with durations

SELECT datetime(ZOBJECT.ZSTARTDATE + 978307200,'unixepoch') AS start,
       datetime(ZOBJECT.ZENDDATE   + 978307200,'unixepoch') AS finish,
       ZOBJECT.ZVALUESTRING AS bundle,
       CAST(ZOBJECT.ZENDDATE - ZOBJECT.ZSTARTDATE AS INT) AS secs
FROM ZOBJECT WHERE ZSTREAMNAME = '/app/inFocus'
ORDER BY start DESC;

TCC — privacy grants, most recent first

SELECT datetime(last_modified,'unixepoch') AS modified,
       service, client, client_type, auth_value, auth_reason
FROM access ORDER BY last_modified DESC;

ExecPolicy — first execution of each binary

SELECT datetime(timestamp,'unixepoch') AS first_seen,
       responsible_path, file_identifier
FROM policy_scan_cache ORDER BY timestamp DESC;

Safari — history with visit counts

SELECT datetime(v.visit_time + 978307200,'unixepoch') AS ts,
       i.url, i.visit_count, v.title
FROM history_visits v JOIN history_items i ON i.id = v.history_item
ORDER BY v.visit_time DESC;

Chrome — history (WebKit epoch)

SELECT datetime(last_visit_time/1000000 - 11644473600,'unixepoch') AS ts,
       url, title, visit_count
FROM urls ORDER BY last_visit_time DESC;

Messages — conversations with handles

SELECT datetime(m.date/1000000000 + 978307200,'unixepoch') AS ts,
       h.id AS contact, m.is_from_me, m.text
FROM message m LEFT JOIN handle h ON h.ROWID = m.handle_id
ORDER BY m.date DESC LIMIT 200;
● NOTE — chat.db USES NANOSECONDS SINCE 2001

Note the /1000000000 in that last query. Messages switched from seconds to nanoseconds in the Mac-absolute epoch around macOS 10.13. If your dates come out in 2001, the column is in nanoseconds and you divided by nothing; if they come out absurdly far in the future, it is in seconds and you divided anyway. Test on a message whose date you can verify.

Any table — find backdated rows

-- rowids are monotonic; a low timestamp at a high rowid was inserted late
SELECT ROWID, datetime(<timecol> + 978307200,'unixepoch') AS ts
FROM <table> ORDER BY ROWID;

ECommand quick-reference card

Setup

IMG=/evidence/mbp-001.dd
OFF=1024040          # sectors
BOFF=$((OFF*512))    # bytes
LOOP=$(sudo losetup -r -P -f --show $IMG)

Discover

mmls $IMG
pstat -o $OFF $IMG
fsapfsinfo -o $BOFF $IMG
fsapfsinfo -o $BOFF -p 'PW' -f 5 -s $IMG   # snapshots

Mount

fsapfsmount -o $BOFF -p 'PW' $IMG /mnt/apfs
apfs-fuse -v 4 -p 'PW' -o ro ${LOOP}p2 /mnt/data
apfs-fuse -v 4 -p 'PW' -s SNAPNAME -o ro ${LOOP}p2 /mnt/snap
fusermount3 -u /mnt/data

Write-block

sudo blockdev --setro $LOOP
truncate -s 64G /var/tmp/cow.img
COW=$(sudo losetup -f --show /var/tmp/cow.img)
SZ=$(sudo blockdev --getsz $LOOP)
echo "0 $SZ snapshot $LOOP $COW P 8" | \
  sudo dmsetup create evid-cow

Sleuth Kit

fsstat -o $OFF -B $DAT $IMG
fls   -o $OFF -B $DAT -r -p $IMG
fls   -o $OFF -B $DAT -r -p -d $IMG   # deleted
istat -o $OFF -B $DAT $IMG <inode>
icat  -o $OFF -B $DAT $IMG <inode> > out
tsk_recover -o $OFF -B $DAT -e $IMG out/

Timeline

fls -o $OFF -B $DAT -r -m / $IMG > body.txt
mactime -b body.txt -d -z UTC > tl.csv
log2timeline.py --storage_file p.db \
  --credential password:'PW' $IMG
psort.py -o dynamic -w super.csv p.db

GFurther reading and sources

Primary specification

  • Apple File System Reference — Apple's own on-disk format document. The authority for every structure named in Part IV. Terse, complete, occasionally out of date on newer features.

Tooling

  • libyal/libfsapfs — the documentation directory contains the most thorough independent write-up of APFS internals available, including encryption.
  • sgan81/apfs-fuse, linux-apfs/linux-apfs-oot, linux-apfs/apfsprogs
  • ydkhatri/mac_apt — and its wiki, which documents artifact locations per macOS version.
  • mandiant/macos-UnifiedLogs — plus Mandiant's write-ups on the tracev3 format.
  • mac4n6/APOLLO — Sarah Edwards' module set; the modules themselves are a reference on pattern-of-life databases.

Practice

  • Sarah Edwards, Mac and iOS Forensic Analysis and the mac4n6 blog — the standard reference for pattern-of-life work.
  • Objective-See's blog and tool set — the best public catalogue of real macOS persistence and malware behaviour. The Malware repository is a legitimate corpus for testing your YARA rules and triage workflow.
  • Patrick Wardle, The Art of Mac Malware — freely available, and the best explanation of why the persistence surfaces in Part VIII are the ones that matter.
■ CAUTION — VERIFY EVERYTHING AGAINST YOUR OWN IMAGE

This manual, like every macOS forensics reference, describes a moving target. Paths change between point releases, tools change behaviour between commits, and Apple documents its filesystem when it feels like it. Where a finding matters, confirm the artifact exists where this document says it does, on your build number, and record the version you observed. Treat every path here as a strong hint rather than a guarantee — that is the correct posture for the whole field, not a weakness of this document.
