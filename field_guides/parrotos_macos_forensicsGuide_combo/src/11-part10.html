60mac_apt on Linux

The most complete open macOS artifact suite. Roughly forty plugins covering most of Part VII, producing SQLite, XLSX and CSV output. It runs on Linux, though the reliable input mode there is MOUNTED against your FUSE mount rather than reading the encrypted image directly.

cd ~/tools/mac_apt && pip install -r requirements.txt

# see what is available before committing to a long run
python3 mac_apt.py -h | sed -n '/plugins/,$p'

# full run against the mounted Data volume
python3 mac_apt.py -o ~/cases/001/06-analysis/macapt -x xlsx \
    MOUNTED /mnt/data/apfs5 ALL

# or targeted, which is far faster when you know what you want
python3 mac_apt.py -o ~/cases/001/06-analysis/macapt \
    MOUNTED /mnt/data/apfs5 \
    UNIFIEDLOGS FSEVENTS QUARANTINE SPOTLIGHT SAFARI CHROME \
    RECENTITEMS AUTOSTART INSTALLHISTORY USERS NETWORKING WIFI NOTIFICATIONS
■ CAUTION — RUN IT AGAINST THE SYSTEM VOLUME SEPARATELY

MOUNTED mode points at one volume. Pointed at the Data volume it will not see /System/Library/LaunchDaemons, because that is on the System volume (§12.3). Either run it twice, once per volume, or point it at the reconstructed unified view from §12.4. A single Data-volume run silently produces an incomplete autostart picture.

▸ TIP — AND AGAINST EVERY SNAPSHOT

The same argument as everywhere else in this manual. Script it across all mounted snapshots and diff the resulting databases; you get a per-snapshot artifact history essentially for free.

for m in /mnt/snap*; do
     python3 ~/tools/mac_apt/mac_apt.py -o ~/cases/001/06-analysis/macapt-$(basename $m) \
       MOUNTED $m AUTOSTART QUARANTINE RECENTITEMS
   done

61APOLLO and pattern-of-life correlation

APOLLO runs several hundred curated queries across the pattern-of-life databases from §28 and normalises everything onto one timeline. It is the fastest route from "I have knowledgeC.db" to "here is what the user was doing".

# gather the databases APOLLO wants, preserving structure
mkdir -p ~/cases/001/03-extract/pol
cp -a /mnt/data/apfs5/private/var/db/CoreDuet          ~/cases/001/03-extract/pol/
cp -a /mnt/data/apfs5/private/var/db/powerlog          ~/cases/001/03-extract/pol/
cp -a "/mnt/data/apfs5/Users/jdoe/Library/Application Support/Knowledge" \
      ~/cases/001/03-extract/pol/

cd ~/tools/APOLLO
python3 apollo.py -o csv -p macos ~/cases/001/03-extract/pol/
head -5 apollo.csv
▸ TIP — MERGE IT INTO THE SUPER-TIMELINE

APOLLO's CSV drops straight into Timesketch alongside the plaso timeline and the parsed unified log. Three independent views of the same hours, on one axis, is where correlation actually happens — and it is exactly the setup §53 assumes.

62Rolling your own

Eventually you need something no tool does. The two useful entry points are pyfsapfs for structural work and plain filesystem walking for artifact work.

62.1 Structural, via pyfsapfs

python3 - <<'PY'
import pyfsapfs

c = pyfsapfs.container()
c.open('/evidence/mbp-001.dd')          # some builds want an offset-aware file object

print('volumes:', c.number_of_volumes)
for i in range(c.number_of_volumes):
    v = c.get_volume(i)
    print(f'{i}: {v.name}  encrypted={v.is_locked()}')
    if v.is_locked():
        v.set_password('TheUserPassword')
        v.unlock()
    print('   snapshots:', v.number_of_snapshots)

def walk(entry, path=''):
    """Yield every file entry with its reconstructed path."""
    for i in range(entry.number_of_sub_file_entries):
        ch = entry.get_sub_file_entry(i)
        p = f'{path}/{ch.name}'
        yield ch, p
        if ch.number_of_sub_file_entries:
            yield from walk(ch, p)
PY

62.2 Artifact work over the mount

For most tasks the mount is enough and far simpler. A pattern that comes up constantly — sweep a tree, parse a format, emit timeline rows:

python3 - <<'PY'
import os, plistlib, csv, sys, datetime as dt

ROOTS = ['/mnt/data/apfs5/Library/LaunchDaemons',
         '/mnt/data/apfs5/Library/LaunchAgents']
w = csv.writer(sys.stdout)
w.writerow(['mtime','path','label','program','runatload','keepalive'])

for root in ROOTS:
    for dirpath, _, files in os.walk(root):
        for fn in files:
            if not fn.endswith('.plist'): continue
            p = os.path.join(dirpath, fn)
            try:
                with open(p,'rb') as f: d = plistlib.load(f)
            except Exception as e:
                w.writerow(['', p, f'UNPARSEABLE: {e}', '', '', '']); continue
            prog = d.get('Program') or ' '.join(d.get('ProgramArguments', []))
            w.writerow([
                dt.datetime.utcfromtimestamp(os.path.getmtime(p)).isoformat(),
                p, d.get('Label',''), prog,
                d.get('RunAtLoad',''), bool(d.get('KeepAlive'))])
PY
▸ TIP — EMIT TIMELINE ROWS, NOT REPORTS

Have every script you write output a row per event with an ISO-8601 UTC timestamp in the first column. Then everything you build merges with everything else, and with plaso, with one sort. Scripts that print prose have to be re-read; scripts that emit timeline rows compound.

63Findings, manifests and defensibility

63.1 The shape of a finding

Every reported finding should carry six things. If you cannot supply all six, it is a lead, not a finding.

ElementExample
ArtifactLaunch agent plist, full original path, on the Data volume
EvidenceSHA-256 of the extracted file; inode number; the exhibit it belongs to
MethodExtracted via apfs-fuse <commit>, parsed with plistutil 2.3.0
ObservationWhat the artifact literally says — quoted, not paraphrased
InterpretationWhat you conclude, and explicitly flagged as interpretation
CorroborationThe independent witnesses (§53) that agree, and any that do not

63.2 Worked example

Finding 3 — Backdated persistence mechanism

Artifact. /Users/jdoe/Library/LaunchAgents/com.apple.softwareupdated.plist (Data volume, inode 2100002). SHA-256 9c1f…4b70. Exhibit 1, extracted 2026-08-02.

Observation. A launch agent labelled com.apple.softwareupdated with RunAtLoad true, KeepAlive true, executing /usr/local/bin/sysupd. The inode records a creation time of 2019-03-14 09:12:00 UTC and a change time of 2026-07-30 02:39:11 UTC.

Interpretation. The file was created on 2026-07-30 and its timestamps subsequently altered to appear historic. The label imitates an Apple service; genuine Apple launch agents reside on the sealed System volume, not in a user's LaunchAgents directory.

Corroboration. (i) Inode 2100002 falls between inodes created at 02:38:44 and 02:38:51 on 2026-07-30. (ii) All four timestamps carry zero nanoseconds, indicating they were set programmatically. (iii) The file is absent from the local snapshot taken 2026-07-30 02:15 and present in the snapshot taken 03:15. (iv) FSEvents records a creation event for that path with no corresponding event in 2019. (v) No settimeofday event appears in the unified log for the relevant period, excluding a system clock change as an explanation.

63.3 Manifests and reproducibility

# hash every exhibit and every derived product
hashdeep -c sha256 -r ~/cases/001/07-report/exhibits > ~/cases/001/07-report/exhibits.manifest

# record the environment that produced the findings
{ uname -a; lsb_release -a; fls -V; fsapfsinfo -V;
   git -C ~/tools/apfs-fuse rev-parse --short HEAD;
   pip freeze; } > ~/cases/001/07-report/toolchain.txt
■ CAUTION — SEPARATE OBSERVATION FROM INTERPRETATION, ALWAYS

"The plist executes /usr/local/bin/sysupd at load" is an observation and is not open to argument. "The machine was compromised" is an interpretation and is. Keeping them in separate, labelled sentences means that if an interpretation is later challenged or overturned, your observations — and the rest of the report — survive intact. Reports that blend the two lose everything when one inference fails.
